บันทึกการแก้ไขปัญหา DataTables Ajax Error (TN/7)

1. รายละเอียดปัญหาที่พบ

บนหน้าจอจัดการการชำระเงินค่าส่วนกลาง (manage_common_fee_payment.php) เมื่อผู้ใช้ป้อนข้อมูลบ้านเลขที่ลงในช่องค้นหา search_house_number และกดค้นหา (Search) ระบบจะแสดงข้อความเตือน:

DataTables warning: table id=TableRecordList - Ajax error. For more information about this error, please see http://datatables.net/tn/7

2. สาเหตุของปัญหา (Root Cause)

ปัญหาเกิดขึ้นที่ฝั่ง Backend ในส่วนประมวลผลฐานข้อมูลสำหรับ DataTable ของไฟล์ model/manage_common_fee_payment_process.php โดยมีขั้นตอนดังนี้:

  • เมื่อมีการป้อนข้อมูลค้นหาเลขที่บ้าน ระบบจะสร้างเงื่อนไข SQL ของตัวแปร $searchQuery ดังนี้: 
    $searchQuery = " AND house_number = :house_number_exact ";
  • ก่อนที่จะส่งคำสั่ง SQL ไปเตรียมการ (Prepare Statement) ระบบมีการใช้ฟังก์ชัน str_replace เพื่อเติม Table Alias (เช่น h. หรือ house.) ให้กับชื่อคอลัมน์โดยอัตโนมัติ: 
    str_replace(['doc_id', 'house_number', 'detail', 'alley', 'remark'], ['h.doc_id', 'h.house_number', 'h.detail', 'house.alley', 'h.remark'], $searchQuery)
  • ผลลัพธ์จาก str_replace ส่งผลเสียคือ มันไปแทนที่ข้อความ house_number ที่อยู่ภายในชื่อของ PDO Placeholder :house_number_exact ด้วย ทำให้กลายเป็นชื่อ :h.house_number_exact
  • ในขณะที่คำสั่งการผูกตัวแปร (PDO Bind Value) ด้านล่างยังระบุผูกกับชื่อตัวแปรเดิม: 
    $stmt->bindValue(':house_number_exact', $searchHouseNumber, PDO::PARAM_STR);
  • การที่ใน SQL มีการเรียกใช้ :h.house_number_exact แต่ผูกตัวแปรจริงให้กับ :house_number_exact ส่งผลให้ PDO ทำงานไม่สำเร็จและโยน PDOException (SQLSTATE[HY093]: Invalid parameter number) ออกมา ซึ่งทำให้เกิด Ajax Error 500 ส่งกลับไปที่ฝั่งหน้าบ้าน

นอกจากนี้ ยังพบปัญหาเดียวกันในการสืบค้นของหน้าอนุมัติการชำระเงินในไฟล์ model/manage_common_fee_payment_approve_process.php ซึ่งชื่อ Placeholder :house_number ถูก str_replace แปลงผิดรูปเป็น :h.house_number เช่นกัน

3. วิธีการแก้ไข (The Fix)

แก้ไขโดยหลีกเลี่ยงการใช้ str_replace ที่มีความเสี่ยงในการแทนที่แบบคาดไม่ถึง และเปลี่ยนมาเขียนคิวรี่ที่ระบุ Table Alias (h. หรือ house.) ลงไปตรงๆ ตั้งแต่เริ่มกำหนดค่า:

การแก้ไขไฟล์ model/manage_common_fee_payment_process.php

เขียน SQL Query แยกตามเงื่อนไขที่ถูกต้องโดยไม่ต้องพึ่งพา str_replace:

// ส่วนกำหนดตัวแปรสืบค้น
$searchQuery = " ";
if ($searchHouseNumber != '') {
    $searchQuery = " AND h.house_number = :house_number_exact ";
    $searchArray['house_number_exact'] = $searchHouseNumber;
} elseif ($searchValue != '') {
    $searchQuery = " AND (h.doc_id LIKE :search1 OR 
                         h.house_number LIKE :search2 OR 
                         h.detail LIKE :search3 OR 
                         house.alley LIKE :search4 OR 
                         h.remark LIKE :search5) ";
    // กำหนดค่าค้นหาลงใน $searchArray...
}

$where_house_number = " ";
$where_house_number_qualified = " ";
if ($_SESSION['account_type'] === "user") {
    $where_house_number = " AND house_number = '" . $_SESSION['house_number'] . "'";
    $where_house_number_qualified = " AND h.house_number = '" . $_SESSION['house_number'] . "'";
}

// ในส่วนประกอบคำสั่ง SQL คิวรี่
$sql_getdata = "SELECT COUNT(h.id) AS allcount FROM ims_house_payment h 
                LEFT JOIN ims_house house ON h.house_number = house.house_number
                WHERE 1=1 " . $searchQuery . $where_house_number_qualified;

การแก้ไขไฟล์ model/manage_common_fee_payment_approve_process.php

ปรับใช้แนวทางเดียวกันโดยใช้คิวรี่แบบระบุ Table Alias โดยตรงและลบการใช้งาน str_replace ออกทั้งหมด:

$searchQuery = " ";
if ($searchValue != '') {
    $searchQuery = " AND (h.house_number LIKE :house_number) ";
    $searchArray = array(
        'house_number' => "%$searchValue%"
    );
}
// เรียกใช้ต่อท้าย WHERE 1=1 ด้วย $searchQuery และ $where_house_number_qualified ตรงๆ

4. ผลลัพธ์และการตรวจสอบ

  • ทำการทดสอบไวยากรณ์โค้ดด้วยคำสั่ง php -l พบว่าไม่มีข้อผิดพลาด (Syntax OK)
  • เมื่อฝั่งเซิร์ฟเวอร์ประมวลผลคำสั่ง SQL ได้อย่างถูกต้อง ระบบจะไม่เกิด Exception อีกต่อไป ส่งผลให้ตาราง DataTable ในหน้าต่าง manage_common_fee_payment.php และหน้าอนุมัติอื่นๆ สามารถแสดงผลข้อมูลสืบค้นตามที่ผู้ใช้กรอกได้อย่างปกติ
