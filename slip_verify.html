AI & FinTech Integration

ระบบตรวจสอบสลิปโอนเงินอัตโนมัติ (Automated Slip Verification)

แนวคิด เทคโนโลยี สถาปัตยกรรม และขั้นตอนการพัฒนาระบบตรวจสอบสลิปด้วย AI และ API สำหรับนักพัฒนา

เทคโนโลยีที่ควรเลือกใช้ (Technology Stack)

การสร้างระบบตรวจสอบสลิปที่มีประสิทธิภาพและปลอดภัยสูง ไม่ควรพึ่งพาการสแกนรูปภาพด้วย AI OCR เพียงอย่างเดียว เนื่องจากไม่สามารถรับประกันความถูกต้องของยอดเงินโอนจริงได้ 100% (ป้องกันกรณีสลิปตัดต่อ) ทางเลือกที่ดีที่สุดคือ การผสมผสานระบบสแกน QR Code เพื่อดึงข้อมูล API ควบคู่กับ AI OCR เป็นแผนสำรอง

1. QR Verification API (หัวใจหลัก)

ใช้ตรวจสอบข้อมูลธุรกรรมดิจิทัลกับธนาคารโดยตรงจาก Mini-QR Code (Slip QR) ที่อยู่บนสลิปโอนเงิน

  • SlipOK API / EasySlip API: บริการยอดนิยมของไทย เชื่อมต่อง่าย ตรวจเช็คข้อมูลสลิปได้แบบ Real-time
  • Direct Bank OpenAPI: ต่อตรงกับธนาคาร (เช่น SCB, KBank Developer) เหมาะกับองค์กรขนาดใหญ่
2. AI OCR / Document AI (สำรอง & ตรวจสอบ)

ใช้กรณีที่สลิปไม่มี QR Code หรือสแกน QR ไม่ได้ โดยการดึงรายละเอียดข้อความจากรูปภาพสลิป

  • Gemini 1.5 Flash API: อ่านภาพสลิปวิเคราะห์และแปลงเป็น JSON ได้อย่างรวดเร็วและแม่นยำ
  • Google Cloud Document AI: มี Model เฉพาะทางด้านสแกนเอกสารทางการเงิน
3. QR Detector Libraries (ฝั่ง Client / Server)

ไลบรารีสำหรับแกะรหัสภาพ QR Code ออกมาเป็นข้อความข้อมูลดิบ (Raw Payload)

  • jsQR / Html5-QrCode (JS): สแกนและถอดรหัสบนเว็บเบราว์เซอร์ฝั่งลูกค้าทันที ลดโหลดของเซิร์ฟเวอร์
  • ZXing (PHP / Java): ถอดรหัสฝั่งเซิร์ฟเวอร์เพื่อประมวลผลซ้ำเป็นมาตรการความปลอดภัย
4. Image Pre-processing (การเตรียมรูปภาพ)

การปรับปรุงรูปภาพสลิปเพื่อให้ไลบรารีถอดรหัส QR Code และ OCR ทำงานได้มีประสิทธิภาพสูงสุด

  • GD Library / ImageMagick: ครอปตัดเฉพาะส่วน QR (ปกติอยู่ 45% ล่างของสลิป)
  • ปรับภาพเป็น Grayscale, ปรับ Contrast และลบสัญญาณรบกวน (Denoise) เพื่อให้อ่านภาพชัดเจนขึ้น
ข้อดีของระบบแบบผสมผสาน (Hybrid): หากมี QR Code ระบบจะตรวจเช็คผ่าน API ทันทีซึ่งปลอดภัย 100% แต่หากรูปภาพเสียหายหรือไม่มี QR ระบบจะใช้ AI OCR สแกนข้อความตัวอักษรแทน เพื่อนำเข้าสู่กระบวนการตรวจสอบโดยมนุษย์ (Manual Verification) ต่อไป

สถาปัตยกรรมการทำงานร่วมกัน (Hybrid Architecture)

โครงสร้างระบบตรวจสอบแบบ Double-Check Pipeline ทำหน้าที่สกัดข้อมูลจากภาพและจับคู่ความถูกต้องของรายการชำระเงินกับฐานข้อมูลเพื่อตัดสิทธิ์การใช้ซ้ำ

อัปโหลดรูปภาพสลิป (Customer Upload Slip)
Image Pre-processing (ครอปภาพ / ปรับสี Grayscale)
พยายามถอดรหัส QR Code (QR Detector)
กรณีพบ QR Code ส่ง Payload ตรวจสอบกับ
Bank/Slip API (เช่น SlipOK)
กรณีไม่พบ QR Code ส่งภาพให้
AI OCR / Gemini API ดึงข้อมูลตัวอักษร
ระบบป้องกันความซ้ำซ้อน (Anti-Double Spend Check / Database Unique)
อัปเดตสถานะสำเร็จ (Auto-Approve) หรือ ส่งให้แอดมินตรวจมือ (Pending Admin)

การเปรียบเทียบแนวทางดึงข้อมูลสลิป

คุณลักษณะ 1. การเช็คผ่าน QR API (SlipOK / EasySlip) 2. การใช้ AI OCR (Gemini / Document AI)
ความแม่นยำ สูงมาก (100%) เนื่องจากดึงข้อมูลตรงจากธนาคาร ปานกลาง-สูง (90-95%) ขึ้นอยู่กับความคมชัดของภาพ
ความปลอดภัยทางธุรกรรม ป้องกันสลิปตัดต่อได้ 100% (ข้อมูลส่งจาก API ธนาคาร) ไม่ปลอดภัยจากการตัดต่อภาพ (เพราะดึงเฉพาะสิ่งที่เห็นบนภาพ)
ข้อจำกัด ต้องมี QR Code บนสลิปเท่านั้น และมีค่าบริการต่อการเรียกใช้งาน ใช้โควต้า API ฟรี/จ่ายเงินตามขนาดไฟล์ อาจมีความล่าช้าในการอ่านภาพ
การประยุกต์ใช้ ใช้เป็นระบบหลัก (Primary Engine) สำหรับระบบอัตโนมัติ ใช้เป็นแผนสำรอง (Fallback) หรือช่วยครอสเช็คการตัดต่อสลิป

ขั้นตอนการทำงานของระบบ (Step-by-Step Implementation)

แนวทางการออกแบบขั้นตอนตั้งแต่ผู้ใช้อัปโหลดรูปภาพจนถึงการยืนยันเงินเข้าบัญชีบริษัท:

  1. ขั้นตอนที่ 1: ขั้นตอนการรับรูปภาพและแปลงสภาพภาพ (Upload & Preprocessing)

    ผู้ใช้อัปโหลดภาพสลิป ระบบจะบันทึกไฟล์ภาพต้นฉบับ จากนั้นระบบจะสร้างรูปคัดลอกใหม่เพื่อประมวลผล (เช่น ลดขนาดรูปภาพให้อยู่ในความกว้างไม่เกิน 1000px, ทำเป็น Grayscale และปรับ Contrast เพื่อให้อ่าน QR Code ง่ายขึ้น)

  2. ขั้นตอนที่ 2: ถอดรหัสข้อมูล QR Code บนภาพ (Scan QR)

    โปรแกรมทำการตรวจจับสัญลักษณ์ QR Code จากรูปภาพ หากตรวจพบ ระบบจะทำการถอดรหัสข้อความที่อยู่ใน QR (ซึ่งส่วนใหญ่จะเป็น URL หรือข้อมูลดิบตามมาตรฐาน EMVCo เช่น 000201010212303000...)

  3. ขั้นตอนที่ 3: ตรวจสอบข้อมูลธุรกรรมผ่าน API (Transaction Inquiry)

    ระบบส่งข้อมูลดิบของ QR ที่แกะได้ไปยังผู้ให้บริการตรวจสลิป (เช่น SlipOK) เพื่อดึงผลลัพธ์ข้อมูลการโอนที่แท้จริงจากธนาคาร เช่น:
    - ยอดเงินโอน (Amount)
    - ชื่อ-นามสกุล ผู้รับโอนปลายทาง (ต้องเป็นบัญชีของบริษัทเราเท่านั้น)
    - วันและเวลาที่ทำรายการสำเร็จ
    - รหัสอ้างอิงธุรกรรม (Transaction Reference ID / Sending Bank)

  4. ขั้นตอนที่ 4: การป้องกันความปลอดภัยและตรวจสอบความถูกต้องเชิงตรรกะ (Business Logic Rules)

    - ป้องกันสลิปวนใช้ซ้ำ (Anti-Double Spend): เช็คว่าเลขที่อ้างอิงการโอนนี้ เคยถูกยืนยันในฐานข้อมูลของระบบเราไปแล้วหรือยัง
    - เช็คยอดเงิน (Amount Match): เช็คว่ายอดเงินโอนตรงกับยอดเงินที่ระบบสั่งให้โอนชำระหรือไม่
    - เช็คบัญชีรับเงิน (Receiver Account Match): ตรวจสอบว่าเงินโอนเข้าบัญชีถูกธนาคารและถูกชื่อเจ้าของบัญชีบริษัท

  5. ขั้นตอนที่ 5: แผนสำรองกรณีไม่มี QR หรือ API ล้มเหลว (AI OCR Fallback)

    หากสลิปนั้นไม่มี QR Code ระบบจะเรียกใช้ AI OCR เช่น Gemini 1.5 Flash API เพื่ออ่านรายละเอียดตัวอักษร จากนั้นระบบจะตั้งค่าให้เป็นสถานะ รอแอดมินยืนยันมือ (Pending Manual Approval) เพื่อความปลอดภัย พร้อมไฮไลท์ข้อมูลที่ AI อ่านพบให้แอดมินเปรียบเทียบดูได้ทันที

ตัวอย่างการติดตั้งและโค้ดตัวอย่าง (Integration Examples)

เพื่อนำแนวคิดไปประยุกต์ใช้จริง นี่คือตัวอย่างโครงสร้างฐานข้อมูลและโค้ดตัวอย่างในภาษา PHP สำหรับการรวมระบบ:

1. การสร้างตารางข้อมูลเพื่อป้องกันการใช้สลิปซ้ำ (SQL Schema)

SQL Schema mysql 
CREATE TABLE verified_slips (
    id INT AUTO_INCREMENT PRIMARY KEY,
    transaction_ref_id VARCHAR(100) NOT NULL UNIQUE, -- รหัสอ้างอิงธุรกรรมธนาคาร (เช่น KBank FT12345)
    sender_bank_code VARCHAR(10) NOT NULL,          -- รหัสธนาคารผู้โอน (เช่น KBANK, SCB, BBL)
    sender_name VARCHAR(150),                       -- ชื่อผู้โอนเงิน
    receiver_name VARCHAR(150),                     -- ชื่อผู้รับโอน (ตรวจสอบว่าเป็นชื่อบริษัทเราหรือไม่)
    amount DECIMAL(10, 2) NOT NULL,                 -- ยอดเงินที่โอนจริง
    transaction_datetime DATETIME NOT NULL,         -- วันที่เวลาตามสลิป
    raw_qr_payload TEXT,                            -- ข้อมูลดิบของ QR code
    order_id VARCHAR(50),                           -- เชื่อมโยงกับคำสั่งซื้อของระบบเรา
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

2. การเรียกใช้ SlipOK API ในการตรวจสอบ (PHP)

verify_slip.php php 
<?php
function verifySlipWithSlipOK($qrCodeText, $expectedAmount, $orderId, $conn) {
    $api_key = "YOUR_SLIPOK_API_KEY";
    $api_url = "https://api.slipok.com/api/v1/verify"; // หรือ URL ตามแพ็คเกจบริการ

    // ส่งคำขอแบบ POST ไปยัง SlipOK API
    $ch = curl_init($api_url);
    curl_setopt($ch, CURLOPT_RETURNTRANSFER, true);
    curl_setopt($ch, CURLOPT_POST, true);
    curl_setopt($ch, CURLOPT_POSTFIELDS, json_encode([
        "log" => true,
        "data" => $qrCodeText
    ]));
    curl_setopt($ch, CURLOPT_HTTPHEADER, [
        "Content-Type: application/json",
        "x-authorization: " . $api_key
    ]);

    $response = curl_exec($ch);
    $err = curl_error($ch);
    curl_close($ch);

    if ($err) {
        return ["status" => "error", "message" => "API Connection Error: " . $err];
    }

    $result = json_decode($response, true);
    
    if (isset($result['success']) && $result['success'] == true) {
        $data = $result['data'];
        $transRef = $data['transRef']; // รหัสธุรกรรม
        $amount = (float)$data['amount']; // ยอดเงินจริง
        $receiverName = $data['receiver']['name']; // ชื่อผู้รับเงิน
        
        // 1. ตรวจสอบการโอนสลิปซ้ำซ้อน (Anti-Double Spend)
        $stmt = $conn->prepare("SELECT id FROM verified_slips WHERE transaction_ref_id = ?");
        $stmt->execute([$transRef]);
        if ($stmt->fetch()) {
            return ["status" => "failed", "message" => "สลิปโอนเงินนี้เคยถูกใช้งานไปแล้วในระบบ"];
        }

        // 2. ตรวจสอบยอดเงินให้ตรงกับที่สั่งซื้อ
        if (abs($amount - $expectedAmount) > 0.01) { // เผื่อผลต่างทศนิยมเล็กน้อย
            return ["status" => "failed", "message" => "ยอดโอนจริงไม่ตรงกับยอดสั่งซื้อ (โอนจริง: " . $amount . ")"];
        }

        // 3. ตรวจสอบผู้รับเงินว่าเป็นบริษัทเราหรือไม่
        $company_name = "บริษัท พีเอสโฮม จำกัด";
        if (strpos($receiverName, $company_name) === false) {
            return ["status" => "failed", "message" => "ผู้รับเงินปลายทางไม่ใช่บัญชีบริษัทของเรา"];
        }

        // บันทึกธุรกรรมลงฐานข้อมูลหากผ่านเงื่อนไขทั้งหมด
        $insert = $conn->prepare("INSERT INTO verified_slips (transaction_ref_id, sender_bank_code, sender_name, receiver_name, amount, transaction_datetime, raw_qr_payload, order_id) VALUES (?, ?, ?, ?, ?, ?, ?, ?)");
        $insert->execute([
            $transRef,
            $data['sendingBank'],
            $data['sender']['name'],
            $receiverName,
            $amount,
            $data['transDate'] . ' ' . $data['transTime'],
            $qrCodeText,
            $orderId
        ]);

        return ["status" => "success", "message" => "ยืนยันยอดเงินโอนเรียบร้อย", "data" => $data];
    } else {
        return ["status" => "failed", "message" => "ไม่สามารถตรวจสอบสลิปนี้ได้ หรือเป็นสลิปปลอม"];
    }
}
?>

3. ระบบสำรอง: การเรียกใช้ Gemini API วิเคราะห์สลิป (PHP Fallback)

gemini_ocr_fallback.php php 
<?php
function analyzeSlipWithGemini($imagePath) {
    $api_key = "YOUR_GEMINI_API_KEY";
    $url = "https://generativelanguage.googleapis.com/v1beta/models/gemini-1.5-flash:generateContent?key=" . $api_key;

    $imageData = base64_encode(file_get_contents($imagePath));
    $mimeType = mime_content_type($imagePath);

    // สร้าง Prompt ที่เฉพาะเจาะจงเพื่อให้โมเดลตอบกลับเป็นรูปแบบ JSON โครงสร้างตามสั่ง
    $prompt = "วิเคราะห์ข้อมูลสลิปการโอนเงินจากภาพนี้ และตอบเป็นรูปแบบ JSON ต่อไปนี้เท่านั้น ห้ามอธิบายเพิ่มเติมโดยเด็ดขาด: " .
              "{ \"amount\": 0.00, \"date\": \"YYYY-MM-DD\", \"time\": \"HH:mm\", \"sender_name\": \"\", \"receiver_name\": \"\", \"transaction_ref\": \"\" }";

    $payload = [
        "contents" => [
            [
                "parts" => [
                    ["text" => $prompt],
                    [
                        "inlineData" => [
                            "mimeType" => $mimeType,
                            "data" => $imageData
                        ]
                    ]
                ]
            ]
        ]
    ];

    $ch = curl_init($url);
    curl_setopt($ch, CURLOPT_RETURNTRANSFER, true);
    curl_setopt($ch, CURLOPT_POST, true);
    curl_setopt($ch, CURLOPT_POSTFIELDS, json_encode($payload));
    curl_setopt($ch, CURLOPT_HTTPHEADER, ["Content-Type: application/json"]);

    $response = curl_exec($ch);
    curl_close($ch);

    $resArr = json_decode($response, true);
    $text = $resArr['candidates'][0]['content']['parts'][0]['text'] ?? '';
    
    // ทำความสะอาดผลลัพธ์
    $text = trim(str_replace(['```json', '```'], '', $text));
    return json_decode($text, true); // คืนค่าข้อมูลสลิปเป็น Array เพื่อนำไปประมวลผลต่อ
}
?>

มาตรการป้องกันกลโกงและการโกงสลิป (Security Best Practices)

ในการประยุกต์ใช้งานจริงในระบบจ่ายเงิน มีกลโกงยอดนิยมที่มักจะเจอกับผู้ทำระบบ หากเราใช้เพียง AI ในการสแกนธรรมดา นี่คือ 3 มาตรการป้องกันที่ต้องปิดช่องโหว่ทันที:

1. กลโกง: การวนรูปภาพสลิปเดิม (Double Spend)

วิธีแก้: ออกแบบให้คอลัมน์ transaction_ref_id ในตารางฐานข้อมูลเป็น UNIQUE INDEX ทุกครั้งที่มีการสแกนสลิปสำเร็จ รหัสนี้จะผูกกับระบบและไม่ให้มีซ้ำ หากมีการอัปโหลดซ้ำระบบจะตรวจพบและยกเลิกทันที

2. กลโกง: การตัดต่อภาพเปลี่ยนตัวเลข (Photoshop Fraud)

วิธีแก้: ห้ามตรวจสอบจากข้อความตัวอักษรอย่างเดียว ให้บังคับการสแกน QR Code แล้วดึงข้อมูลจาก API ธนาคาร เนื่องจากข้อมูลจาก API จะเป็นข้อมูลดิบจริงในฐานข้อมูลของธนาคาร แม้ผู้ร้ายจะแต่งรูปสลิปสวยงาม แต่ยอดโอนจริงจาก API จะแสดงค่าจริง (เช่น โอนจริง 1 บาท แต่แต่งรูปเป็น 10,000 บาท ข้อมูลจาก API จะฟ้องว่าเป็น 1 บาท)

3. กลโกง: การสลับเปลี่ยน QR Code (QR Swap Attack)

วิธีแก้: ผู้ร้ายอาจตัดต่อรูปภาพหน้าสลิปมียอดเงิน 10,000 บาท แต่แอบสอดไส้ QR Code ของรายการโอนจริง 1 บาท เพื่อผ่านระบบตรวจสอบอัติโนมัติ
แนวทางป้องกันเชิงลึก (Cross-Check): ให้ใช้ระบบผสมผสาน โดยให้อ่านยอดเงินจาก QR API (ได้ 1 บาท) และให้ AI OCR อ่านยอดเงินที่เขียนอยู่ในกระดาษสลิป (ได้ 10,000 บาท) ถ้ายอดจาก API และ OCR แตกต่างกันเกินกว่าเปอร์เซ็นต์ที่กำหนด ให้ระงับอัติโนมัติและแจ้งเตือนแอดมินให้มาตรวจสอบรูปภาพอีกครั้ง

4. กลโกง: การสแกนสลิปเก่าสะสม

วิธีแก้: นอกจากการตรวจเช็ครหัสอ้างอิงธุรกรรมแล้ว ควรตั้งค่าเงื่อนไขเวลาด้วย เช่น สลิปโอนเงินต้องทำรายการเสร็จสิ้นไม่เกิน 24-48 ชั่วโมงก่อนที่จะนำมาอัปโหลด เพื่อจำกัดความพยายามใช้สลิปเก่า

สรุปคำแนะนำสำหรับนักพัฒนา: สำหรับระบบตัดยอดอัตโนมัติ ไม่ควรอนุมัติอัตโนมัติหากผลลัพธ์มาจากระบบ OCR ตัวหนังสือเพียงอย่างเดียว ควรอนุมัติอัตโนมัติเฉพาะกรณีสแกนผ่าน QR API และผ่านเงื่อนไขตรวจสอบซ้ำแล้วเท่านั้น หากไม่ผ่าน QR แต่สแกน OCR ผ่าน ควรตั้งเป็นสถานะ "รอแอดมินอนุมัติ" เสมอ

ขั้นตอนย่อย B: เรียกใช้ไลบรารี jsQR (มีอยู่แล้วในระบบ) เพื่อตรวจจับและอ่านค่า QR ทันทีที่ลูกค้าอัปโหลดรูปภาพ:

ส่วน Javascript ตรวจจับ QR Code ในหน้าจอ javascript 
// โหลดสคริปต์ jsQR ใน <head> หรือก่อนแท็กปิด </body> หากยังไม่มี
// <script src="https://cdn.jsdelivr.net/npm/jsqr@1.4.0/dist/jsQR.min.js"></script>

$("#picture_payment").on("change", async function () {
    const file = this.files[0];
    if (!file) return;

    const statusDiv = document.getElementById("qr_scan_status");
    const qrPayloadInput = document.getElementById("qr_payload");

    statusDiv.style.display = "block";
    statusDiv.className = "mt-2 text-sm text-info";
    statusDiv.innerHTML = "<i class='fas fa-spinner fa-spin'></i> กำลังประมวลผลและสแกนสลิปโอนเงิน...";
    qrPayloadInput.value = ""; // เคลียร์ค่าเก่า

    // อ่านรูปภาพเพื่อสแกน QR Code ด้วย Canvas
    const reader = new FileReader();
    reader.onload = function(e) {
        const img = new Image();
        img.onload = function() {
            const canvas = document.createElement("canvas");
            const ctx = canvas.getContext("2d");
            canvas.width = img.width;
            canvas.height = img.height;
            ctx.drawImage(img, 0, 0);

            const imageData = ctx.getImageData(0, 0, canvas.width, canvas.height);
            const code = jsQR(imageData.data, imageData.width, imageData.height);

            if (code) {
                // ตรวจพบ QR Code บนสลิป
                qrPayloadInput.value = code.data;
                statusDiv.className = "mt-2 text-sm text-success";
                statusDiv.innerHTML = "<i class='fas fa-check-circle'></i> ตรวจพบรหัสสลิปโอนเงินพร้อมสำหรับการตรวจสอบอัตโนมัติ";
            } else {
                // ไม่พบ QR Code (อาจจะเป็นสลิปแบบเก่า หรือครอปสแกนไม่ติด)
                statusDiv.className = "mt-2 text-sm text-warning";
                statusDiv.innerHTML = "<i class='fas fa-exclamation-triangle'></i> ไม่พบสัญลักษณ์สแกนอัตโนมัติ ระบบจะส่งให้เจ้าหน้าที่ตรวจสอบด้วยมือ";
            }
        };
        img.src = e.target.result;
    };
    reader.readAsDataURL(file);
});

3. การแก้ไของค์ประกอบฝั่งเซิร์ฟเวอร์ (model/manage_payment_transfer_smart.php)

ปรับปรุงสคริปต์หลังบ้านเพื่อรับ qr_payload และนำไปตรวจสอบกับ API ของธนาคาร (เช่น SlipOK) ก่อนบันทึกลงฐานข้อมูล:

model/manage_payment_transfer_smart.php (Backend Logic) php 
// 1. รับค่า qr_payload จาก $_POST
$qr_payload = isset($_POST['qr_payload']) ? trim($_POST['qr_payload']) : '';

$slip_verify_status = 'unverified';
$slip_trans_ref = null;
$slip_raw_data = null;
$slip_verify_method = null;

if (!empty($qr_payload)) {
    // 2. เรียกใช้ฟังก์ชันตรวจสอบสลิปผ่าน API (ดูฟังก์ชันตรวจสอบในแท็กตัวอย่างโค้ด)
    $verify_result = verifySlipWithSlipOK($qr_payload, $amount, $doc_id, $conn);
    
    if ($verify_result['status'] === 'success') {
        $slip_verify_status = 'verified';
        $slip_trans_ref = $verify_result['data']['transRef'];
        $slip_raw_data = json_encode($verify_result['data']);
        $slip_verify_method = 'qr_api';
        
        // ทางเลือก: หากผ่านการยืนยันอัตโนมัติ สามารถปรับปรุงหมายเหตุว่าผ่านการตรวจอัตโนมัติได้
        $remark .= " (ยืนยันสลิปอัตโนมัติ)";
    } else {
        // กรณีตรวจสอบ API แล้วล้มเหลว (เช่น ข้อมูลไม่ตรง ยอดเงินผิด หรือสลิปซ้ำ)
        // เพื่อความปลอดภัยของธุรกรรม แนะนำให้แจ้งข้อผิดพลาดกลับไปหน้าบ้าน
        echo "SLIP_VERIFY_FAILED: " . $verify_result['message'];
        exit;
    }
} else {
    // 3. กรณีไม่มี QR payload (สลิปแบบเก่า หรือ สแกนฝั่ง Client ไม่ผ่าน)
    // สามารถใช้แผนสำรอง AI OCR (Gemini API) เพื่อตรวจจับและสกัดข้อความเพื่อเปรียบเทียบเบื้องต้นได้
    try {
        $upload_dir = '../uploads/slips/';
        $file_path = $upload_dir . $file_name; // พาธรูปภาพสลิปที่เซฟแล้ว
        
        $ocr_data = analyzeSlipWithGemini($file_path);
        if ($ocr_data) {
            $slip_raw_data = json_encode($ocr_data);
            $slip_verify_method = 'ai_ocr';
            
            // เช็คข้อมูลยอดเงินจาก OCR เบื้องต้นเพื่อประกอบการพิจารณาของแอดมิน
            if (isset($ocr_data['amount']) && abs((float)$ocr_data['amount'] - (float)$amount) > 0.01) {
                $slip_verify_status = 'mismatch'; // ยอดเงินไม่ตรงกัน
            }
        }
    } catch (Exception $e) {
        error_log("Gemini Fallback Error: " . $e->getMessage());
    }
}
