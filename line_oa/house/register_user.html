คู่มือการใช้งานและโครงสร้างระบบ LINE OA (House)

รายละเอียดการทำงาน ขั้นตอนการสมัครสมาชิก และฟังก์ชันติดต่อประสานงานนิติบุคคล

1. ภาพรวมระบบ (System Overview)

ระบบ pshome33 บริหารงานหมู่บ้าน ได้รับการพัฒนาขึ้นเพื่อเชื่อมต่อบัญชีผู้ใช้ LINE ของลูกบ้านหมู่บ้านพฤกษา 33 เข้ากับระบบนิติบุคคล (PS33 Home System) ผ่านเทคโนโลยี LINE LIFF (LINE Front-end Framework) ช่วยลดขั้นตอนยุ่งยากในการดาวน์โหลดแอปพลิเคชัน และเอื้อให้นิติบุคคลสามารถส่งข้อความแจ้งเตือนต่างๆ (เช่น ยอดค้างชำระค่าส่วนกลาง ใบรับเงินอิเล็กทรอนิกส์) เข้าสู่ LINE ส่วนตัวของลูกบ้านได้โดยตรง

ระบบลงทะเบียน (LIFF Registration)

ดึงข้อมูล Profile จาก LINE อัตโนมัติ เพื่อให้ลูกบ้านยืนยันตัวตน ผูกเบอร์โทรศัพท์ เลขที่บ้าน และตั้งรหัสผ่านในการล็อกอินเข้าระบบหลัก

ระบบส่งข้อความติดต่อ (LIFF Messaging)

ให้ลูกบ้านแจ้งเรื่อง ร้องเรียน หรือสอบถามนิติบุคคล พร้อมแนบภาพถ่ายหลายรูปพร้อมกัน อัปโหลดตรงเข้าฐานข้อมูลเพื่อรอตรวจสอบ

2. โครงสร้างฐานข้อมูลที่เกี่ยวข้อง (Database Schema)

ในการทำงานของระบบลงทะเบียนและส่งข้อความ LINE OA มีความสัมพันธ์กับตารางหลัก 4 ตารางดังนี้:

ชื่อตาราง ฟิลด์สำคัญ บทบาทหน้าที่ในระบบ
ims_house_line_user line_user_id, line_user_name, line_phone, house_number จัดเก็บความสัมพันธ์ระหว่าง LINE Account กับเลขที่บ้าน และเบอร์โทรศัพท์มือถือที่ลูกบ้านสมัคร
ims_user user_id (เบอร์โทร), password (bcrypt hash), status บัญชีผู้ใช้ระบบหลักสำหรับใช้ล็อกอินเข้าตรวจสอบยอดเงินและการแจ้งซ่อมผ่านหน้า Dashboard
ims_house house_number, contact_name, phone_number, alley ข้อมูลมาสเตอร์บ้านเลขที่ในโครงการ (หากสมัครใหม่แต่ยังไม่มีทะเบียนบ้านนี้ ระบบจะสร้างแถวข้อมูลให้อัตโนมัติ)
afront_contact user_id, remark, photo_path, house_number บันทึกข้อมูลการส่งข้อความสอบถาม/เรื่องร้องเรียนของลูกบ้านพร้อมรูปภาพอัปโหลด

3. ขั้นตอนการลงทะเบียน (Registration Workflow)

กระบวนการลงทะเบียนผ่านไฟล์หลักของระบบ:

1โหลดโปรไฟล์ด้วย LIFF SDK

เมื่อเปิดผ่าน LINE OA หน้า register_house_user จะเรียกใช้ LINE LIFF SDK ในการโหลดข้อมูลของลูกบ้านประกอบด้วย User ID, Display Name, และ URL รูปโปรไฟล์ นำมาแสดงผลบนฟอร์ม

2ตรวจสอบการลงทะเบียนซ้ำ (Client-Side Check)

ระบบจะทำการส่งค่า User ID ไปเช็กที่ register_house_with_line_api ด้วยคำสั่งเช็กสถานะ action: 'check' ทันที หากตรวจพบว่าลงทะเบียนไปแล้ว หน้าฟอร์มจะแสดงกล่องแจ้งเตือนป๊อปอัป "⚠️ คุณลงทะเบียนแล้ว!" พร้อมแสดงชื่อและบ้านเลขที่เดิม และจะปิดปุ่มลงทะเบียนพร้อมล็อกทุกฟิลด์เป็น Read-only

3การกรอกข้อมูลและส่งฟอร์ม (Form Submission)

ลูกบ้านกรอกข้อมูลประกอบด้วย เลขที่บ้าน (ระบบจัดเก็บเฉพาะตัวเลขและเครื่องหมายทับ เช่น 99/99 เท่านั้น), ซอย, ชื่อ-นามสกุลจริง, เบอร์โทรศัพท์ และตั้งรหัสผ่าน ระบบจะส่งข้อมูลผ่าน AJAX แบบ POST ไปประมวลผลที่หลังบ้าน

4ประมวลผล API หลังบ้าน (Server-Side Verification & Storage)

ไฟล์ register_house_with_line_api จะทำงานตามลำดับดังนี้:

  • ตรวจสอบความซ้ำซ้อนของเบอร์โทรศัพท์และ LINE User ID ในฐานข้อมูล หากซ้ำจะปฏิเสธการทำรายการทันที
  • บันทึกความเชื่อมโยง LINE ลงตาราง ims_house_line_user
  • ตรวจสอบตารางผู้ใช้หลัก ims_user หากมีเบอร์โทรนี้แล้วจะทำการอัปเดตรหัสผ่านใหม่และตั้งค่าสถานะเป็น Active หากไม่มีจะลงทะเบียนผู้ใช้ใหม่ให้ทันที
  • ตรวจสอบตารางบ้าน ims_house หากยังไม่เคยมีบ้านเลขที่นี้ในระบบ จะบันทึกเลขที่บ้านและที่อยู่ลงฐานข้อมูลกลางให้ทันที
5การแจ้งเตือนกลับในแชท LINE (LINE Message Push)

หลังจากเซิร์ฟเวอร์บันทึกสำเร็จ หน้าจอจะแสดงแจ้งเตือนความสำเร็จ และระบบจะส่งข้อความสรุปการลงทะเบียน ✅ ลงทะเบียนสำเร็จ! [ชื่อ] [เลขที่บ้าน] [เบอร์โทร] เข้าไปยังห้องแชทของลูกบ้านโดยอัตโนมัติเพื่อให้รับทราบ

4. ขั้นตอนการส่งข้อความสอบถาม/ร้องเรียน (Messaging Workflow)

นอกจากระบบลงทะเบียนแล้ว ยังมีส่วนให้ลูกบ้านส่งข้อความแจ้งเรื่องเข้ามายังนิติบุคคลได้โดยง่าย:

1กรอกข้อความและอัปโหลดภาพ

ผู้ใช้เข้าหน้า send_message.html (หรือ send_message_line_oa.html) กรอกรายละเอียดเรื่องที่ต้องการแจ้ง และเลือกไฟล์ภาพถ่ายที่เกี่ยวข้อง (ระบบรองรับการอัปโหลดพร้อมกันหลายไฟล์)

2ประมวลผลผ่าน API บันทึกข้อมูล

ส่งข้อมูลภาพและข้อความผ่าน AJAX ไปที่ send_message_api ระบบจะดึงชื่อ นามสกุล และเลขที่บ้านของผู้ใช้จาก LINE User ID ในตาราง ims_house_line_user มาใช้ประกอบเป็นข้อมูลผู้แจ้งโดยอัตโนมัติ

3การจัดการไฟล์และการบันทึกฐานข้อมูล

ภาพที่ส่งขึ้นมาจะถูกบีบอัดและแปลงนามสกุลเป็นไฟล์ .jpg เซฟลงโฟลเดอร์ uploads/ พร้อมระบบตั้งชื่อไฟล์ไม่ซ้ำกันเพื่อความปลอดภัย จากนั้นจึงบันทึกข้อมูลและที่อยู่รูปภาพทั้งหมด (แยกด้วยเครื่องหมายจุลภาค) ลงในตาราง afront_contact เพื่อรอให้นิติบุคคลตรวจสอบผ่านระบบหลังบ้าน

5. บันทึกประวัติและการตรวจสอบระบบ (Logs & Debugging)

ผู้ดูแลระบบสามารถตรวจสอบการทำงาน ข้อผิดพลาด และสถานะของระบบ LINE OA ได้ผ่านไฟล์บันทึก (Log Files) ในโฟลเดอร์นี้:

ชื่อไฟล์ Log รายละเอียดการจัดเก็บข้อมูล
line_house_user_register_log.txt บันทึกข้อมูลการลงทะเบียน (สมัครสำเร็จ / ข้อมูลซ้ำซ้อน / เกิดข้อผิดพลาดของ SQL DB)
line_log.txt บันทึก Raw Request JSON payload ที่ถูกส่งมาจาก LINE Webhook (ใช้ดีบักข้อมูล Webhook)
line_reply_log.txt บันทึกผลการส่งข้อความตอบกลับของบอต (LINE Reply API Response)
line_message_all_log.txt บันทึก Log ข้อความทั้งหมดที่มีการรับส่งกับ LINE OA
⚠️ ข้อควรระวังความปลอดภัย:
  • ไฟล์ Log เหล่านี้มีการเก็บข้อมูลของลูกบ้าน (เช่น User ID, ชื่อ) ควรจำกัดสิทธิ์การเข้าถึงภายนอกผ่านไฟล์ .htaccess ที่ตั้งไว้เพื่อความปลอดภัยของข้อมูลส่วนบุคคล
  • Token ของ LINE Access Token (เช่นในไฟล์ hello_lineoa และ send_message_api) ควรเก็บรักษาเป็นความลับอย่างยิ่ง

6. โครงสร้างไฟล์ทั้งหมดในระบบ (File Structure)

  • register_house_user - หน้าฟอร์มลงทะเบียนลูกบ้านฝั่งหน้าจอ LINE LIFF Frontend UI
  • register_house_with_line_api - API ตรวจเช็กและบันทึกข้อมูลการลงทะเบียน Backend API
  • send_message.html / send_message_line_oa.html - หน้าฟอร์มส่งข้อความ/ร้องเรียนของลูกบ้าน Frontend UI
  • send_message_api - API อัปโหลดไฟล์ภาพและบันทึกข้อความร้องเรียนลง DB Backend API
  • hello_lineoa - สคริปต์ Webhook สำหรับทดสอบรับ/ส่งข้อความกับระบบ LINE Platform Webhook Test
  • howto_change_line.html - คู่มือสั้นแสดงขั้นตอนสำหรับลูกบ้านที่ต้องการเปลี่ยน LINE บัญชีใหม่ User Manual
