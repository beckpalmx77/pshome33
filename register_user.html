คู่มือระบบลงทะเบียนผู้ใช้งาน

สรุปแนวคิด โครงสร้างข้อมูล ขั้นตอน และความสัมพันธ์ในการลงทะเบียนเข้าใช้งานระบบ PS33 Home System

1. แนวคิดการออกแบบระบบ (System Design Concept)

ระบบลงทะเบียนผู้ใช้งานในโครงการ **PS33 Home System** ออกแบบมาเพื่อให้ลูกบ้านเข้าถึงนิติบุคคลและข้อมูลทรัพย์สินของตนเองได้สะดวกรวดเร็วที่สุด ผ่านเทคโนโลยี LINE LIFF (LINE Front-end Framework)

จุดเด่น: ลูกบ้านไม่ต้องติดตั้งแอปพลิเคชันเพิ่มเติม เพียงกดผ่าน LINE OA ระบบจะดึงโปรไฟล์ LINE มาผูกและเชื่อมข้อมูลกับฐานข้อมูลบ้านของหมู่บ้านให้อัตโนมัติทันที

ด้วยแนวคิดการผูกบัญชีครั้งเดียว (One-Time Linkage) นิติบุคคลจะสามารถส่งข้อความแจ้งยอดค้างชำระค่าส่วนกลาง ใบเสร็จรับเงินอิเล็กทรอนิกส์ (E-Receipt) หรือข่าวสารสำคัญผ่านระบบอัตโนมัติยิงตรงเข้าแชท LINE ของลูกบ้านได้อย่างแม่นยำรายบุคคล

2. ข้อมูลและตารางที่เกี่ยวข้อง (Database Architecture)

สถาปัตยกรรมฐานข้อมูลของระบบแบ่งการจัดเก็บออกเป็น 3 ตารางหลัก เพื่อรองรับการทำงานและการสลับเปลี่ยนบัญชีในอนาคต:

ชื่อตาราง ข้อมูลสำคัญที่บันทึก หน้าที่/บทบาทในระบบ
ims_house เลขที่บ้าน (house_number), ชื่อผู้ติดต่อหลัก, เบอร์โทรศัพท์, หมายเลขซอย ข้อมูลมาสเตอร์ของทรัพย์สิน/บ้านแต่ละหลังในหมู่บ้าน (เป็นตารางกลางเชื่อมโยงประวัติบัญชีและการซ่อมแซม)
ims_house_line_user LINE User ID (line_user_id), LINE Display Name, เบอร์โทรสำหรับผูกระบบ LINE (line_phone) เก็บความสัมพันธ์การผูกบัญชี LINE Account เข้ากับเลขที่บ้าน และเบอร์โทรศัพท์ของลูกบ้าน
ims_user Username (user_id ใช้เบอร์โทร), รหัสผ่าน (Hash), สิทธิ์การเข้าถึง (Role) ใช้ควบคุมสิทธิ์การล็อกอินเพื่อดูข้อมูลการเงิน ยอดค้างชำระ และการแจ้งซ่อมของตนเองในหน้า Dashboard

แผนผังความสัมพันธ์ (Relationships):
ims_house_line_user.house_number เชื่อมโยงกับ ims_house.house_number (ผูกตัวตนลูกบ้านเข้ากับที่อยู่หลัก)
ims_house_line_user.line_phone เชื่อมโยงกับ ims_user.user_id (ใช้เบอร์โทรเป็นกุญแจในการเข้าระบบหลัก)

3. ขั้นตอนการลงทะเบียนใช้งาน (Registration Workflow)

1เข้าผ่าน LINE OA (LIFF Initialization)

ลูกบ้านเปิดเมนูลงทะเบียนจาก LINE OA ระบบจะทำการส่งผ่านโปรไฟล์จาก LINE SDK มายังหน้าฟอร์มสมัครสมาชิก line_oa/house/register_house_user.php โดยดึงรูปภาพ ชื่อ Display Name และ LINE User ID ขึ้นมารอโดยอัตโนมัติ

2กรอกข้อมูลส่วนบุคคล

ลูกบ้านกรอกเลขที่บ้าน (รูปแบบ เช่น 99/99), ซอย, ชื่อ-นามสกุลจริง, เบอร์โทรศัพท์เคลื่อนที่ (ที่จะใช้เป็น Username เข้าระบบ) และตั้งรหัสผ่านที่ต้องการ

3การบันทึกฝั่ง API หลังบ้าน

ข้อมูลทั้งหมดจะถูกส่งผ่าน AJAX ไปยัง API line_oa/house/register_house_with_line_api.php:

  • ตรวจสอบความซ้ำซ้อน: เช็กว่า LINE ID หรือเบอร์โทรเคยสมัครแล้วหรือไม่ ป้องกันการลงทะเบียนขัดแย้ง
  • บันทึกตาราง LINE: เพิ่มประวัติการผูกบัญชีลงในตาราง ims_house_line_user
  • สร้าง/อัปเดตสิทธิ์บัญชี: ตรวจเช็กตาราง ims_user หากนิติบุคคลยังไม่มีข้อมูลจะทำการสมัครสมาชิกให้ใหม่ แต่หากมีเบอร์โทรดังกล่าวในระบบนิติบุคคลอยู่แล้ว จะทำการอัปเดตรหัสผ่านใหม่และเปิดใช้งานบัญชี (Status = Active)
  • จัดระบบข้อมูลบ้าน: หากในตาราง ims_house ยังไม่มีข้อมูลที่อยู่ตามเลขที่บ้านนั้น ระบบจะจัดพิมพ์และสร้างข้อมูลมาสเตอร์บ้านหลังดังกล่าวเข้าไปรอโดยอัตโนมัติ
4ส่งการต้อนรับใน LINE

เมื่อประมวลผลสำเร็จ หน้าจอจะแสดงป๊อปอัปยืนยันการลงทะเบียน พร้อมใช้ฟังก์ชัน LINE Bot SDK ส่งการ์ดหรือข้อความต้อนรับเข้าใช้งานระบบโดยตรงในหน้าต่างแชทของลูกบ้าน

4. การจัดการกรณีลงทะเบียนซ้ำ (Duplicate Registration Handling)

ในกรณีที่ลูกบ้านที่เคยสมัครสมาชิกแล้วพยายามจะลงทะเบียนเข้าระบบซ้ำอีกครั้ง ระบบจะมีการบล็อกและจัดการใน 2 ระดับเพื่อป้องกันข้อผิดพลาด:

ระดับหน้าบ้าน (Frontend Check & Lock)

ทันทีที่หน้าจอลงทะเบียนโหลดข้อมูล Profile LINE สำเร็จ ระบบจะยิงคำร้องไปยัง API เพื่อตรวจเช็กสถานะ หากพบว่า LINE ID ดังกล่าวผูกบัญชีแล้ว ระบบจะส่งหน้าจอแจ้งเตือนป๊อปอัป "⚠️ คุณลงทะเบียนแล้ว!" ขึ้นแสดงข้อมูล Name/House Number/Phone ของตนเองทันที และทำการล็อกทุกฟิลด์กรอกข้อมูลเป็น Read-only พร้อมปิดการทำงานปุ่มลงทะเบียน

ระดับหลังบ้าน (Backend API Verification)

หากข้อมูลพยายามยิงส่งตรงเข้าสู่ API register_house_with_line_api.php โดยไม่ผ่านขั้นตอนตรวจสอบหน้าบ้าน ฝั่ง API จะตรวจเช็กค่าของ LINE User ID และ เบอร์โทรศัพท์ กับฐานข้อมูล:

  • หากพบค่าอย่างใดอย่างหนึ่งซ้ำซ้อนในตาราง ims_house_line_user ระบบจะปฏิเสธการบันทึก
  • ย้อนคืนกระบวนการทำงานและตอบกลับข้อผิดพลาด "Line Account - มี User นี้ อยู่ในระบบแล้ว" ส่งผลให้ลูกบ้านสมัครไม่สำเร็จ ข้อมูลไม่ได้รับความเสียหาย

5. มาตรการรักษาความปลอดภัยของข้อมูล

  • Password Hashing: รหัสผ่านของผู้ใช้งานจะถูกเข้ารหัสผ่านฟังก์ชัน password_hash() แบบ bcrypt ก่อนนำลงไปเก็บในตาราง เพื่อความปลอดภัยสูงสุด
  • Input Validation: ฟิลด์กรอกบ้านเลขที่และเบอร์โทรศัพท์มือถือผ่านระบบควบคุมความถูกต้องผ่าน regex คัดกรองและสกัดอักขระพิเศษเพื่อความถูกต้องของฟอร์แมต
  • Log Tracking: ทุกกระบวนการลงทะเบียน ระบบบันทึก Log การสมัครสมาชิกสำเร็จและการทำงานผิดพลาดเข้าสู่ line_house_user_register_log.txt อัตโนมัติ
