👥 1. ผู้กระทำในระบบ (System Actors)

ระบบ TutorMatch AI มีผู้มีส่วนได้ส่วนเสียและระบบภายนอกที่เข้ามามีปฏิสัมพันธ์กับระบบ แบ่งออกเป็น 2 กลุ่มหลัก:

Actor Name ประเภท (Type) บทบาทและหน้าที่ในระบบ (Role & Responsibility)
ผู้เรียน (Student) Primary Human ผู้เรียนหรือผู้ปกครองที่เข้ามาค้นหาผู้สอน ลงทะเบียน ยืนยันตัวตนด้วยใบหน้า ระบุความต้องการภาษาไทย คัดกรองติวเตอร์ และติดต่อนัดหมายเวลาเรียน
ผู้สอน / ติวเตอร์ (Tutor) Primary Human ผู้สอนที่เข้ามาเปิดรับสอนพิเศษ ลงทะเบียน สแกนใบหน้าเพื่อความปลอดภัย บันทึกโปรไฟล์ ความเชี่ยวชาญ สไตล์การสอน อัตราค่าเรียน และพิจารณารับคำขอนัดหมาย
ผู้ดูแลระบบ (Admin) Secondary Human ผู้ดูแลความเรียบร้อยของระบบ ตรวจสอบประวัติการใช้งาน และจำลองชุดข้อมูลติวเตอร์ตัวอย่าง (Mock Data Seed) สำหรับทดสอบระบบ
AI Engine (Biometrics & NLP) Internal Subsystem ระบบตรวจจับและรู้จำใบหน้า (Haar Cascade & LBPH) และระบบประมวลผลภาษาธรรมชาติ (PyThaiNLP Tokenizer + TF-IDF Vectorizer + Cosine Similarity)
LINE Platform (OA & LIFF) External System ช่องทางหน้ากากติดต่อผู้ใช้งาน (LINE Front-end Framework) และระบบส่งข้อความแจ้งเตือน (Messaging API & Flex Messages)

📝 3. รายละเอียดข้อกำหนดการใช้งาน (Use Case Specifications)

UC-01
สมัครสมาชิกและกำหนดบทบาท (User Registration)
Actor: ผู้เรียน (Student), ติวเตอร์ (Tutor)
Pre-condition: ผู้ใช้เปิดหน้าเว็บ LINE LIFF
Main Flow: 1. ผู้ใช้กรอก Username (ภาษาอังกฤษ) และชื่อ-นามสกุลจริง
2. เลือกบทบาทเป็น 'student' หรือ 'tutor'
3. ระบบตรวจสอบ Username ซ้ำ และบันทึกบัญชีลงตาราง User
Post-condition: ได้รับ User ID และนำไปสู่ขั้นตอนสแกนใบหน้า
UC-02
ลงทะเบียนใบหน้าชีวมิติ (Face Biometric Enrollment)
Actor: ผู้เรียน, ติวเตอร์
Pre-condition: มีบัญชีผู้ใช้ในระบบแล้ว และเปิดกล้องเว็บแคม
Main Flow: 1. ผู้ใช้ส่องหน้าตรงในกรอบกล้องบน LIFF
2. กดปุ่มบันทึกรูปเพื่อลงทะเบียนใบหน้า
3. ระบบตรวจจับใบหน้าด้วย Haar Cascade ตัดครอบขนาด 150x150 Grayscale
4. เข้ารหัสเป็น Base64 บันทึกลงตาราง BiometricProfile
Post-condition: เทมเพลตใบหน้าพร้อมใช้งานสำหรับล็อกอิน
UC-03
ล็อกอินยืนยันตัวตนด้วยใบหน้า (Biometric Login)
Actor: ผู้เรียน, ติวเตอร์
Pre-condition: ได้ทำการลงทะเบียนใบหน้าไว้ล่วงหน้าแล้ว
Main Flow: 1. ผู้ใช้กรอก Username และเปิดกล้องเว็บแคม
2. ระบบส่งภาพถ่ายปัจจุบันเทียบกับเทมเพลตเดิมด้วย LBPH Model
3. หากระยะห่าง (Distance) < 75.0 ถือว่าผ่านการยืนยันตัวตน
4. ระบบสร้าง Session อนุญาตให้เข้าสู่ฟังก์ชันตามบทบาท
Exception: Distance >= 75.0 หรือไม่พบใบหน้า แสดงข้อความแจ้งเตือน
UC-04
บันทึกข้อมูลประวัติติวเตอร์ (Manage Tutor Profile)
Actor: ติวเตอร์ (Tutor)
Pre-condition: ยืนยันตัวตนเข้าสู่ระบบในบทบาทติวเตอร์สำเร็จ
Main Flow: 1. กรอกประวัติการศึกษา, รายวิชาที่เปิดสอน (เช่น คณิต, ฟิสิกส์)
2. ระบุรายละเอียดความเชี่ยวชาญ, สไตล์การสอน, อัตราค่าเรียนต่อชั่วโมง
3. กรอก LINE ID, เบอร์โทรศัพท์ และคำแนะนำการนัดหมาย
4. ระบบรวมข้อความสร้าง Index Text บันทึกลง TutorProfile
Post-condition: โปรไฟล์ปรากฏในการค้นหาของ AI Matching Engine
UC-05
ค้นหาและจับคู่ติวเตอร์ด้วย AI (Semantic Tutor Match)
Actor: ผู้เรียน (Student)
Pre-condition: เข้าสู่ระบบในบทบาทผู้เรียน
Main Flow: 1. ผู้เรียนพิมพ์ข้อความความต้องการอิสระภาษาไทย (เช่น 'อยากได้พี่ใจดี สอนฟิสิกส์ ม.ปลาย เน้นปูพื้นฐาน')
2. ระบุวิชาหลักที่เจาะจง และงบประมาณสูงสุดต่อชั่วโมง
3. AI กรองเงื่อนไข Hard Filter (งบประมาณและวิชา)
4. AI ทำ Tokenization ด้วย PyThaiNLP และคำนวณ TF-IDF Cosine Similarity
5. แสดงผลรายชื่อติวเตอร์เรียงตาม Match Score (%) พร้อมประวัติและช่องทางติดต่อ
Post-condition: ผู้เรียนได้รับรายชื่อติวเตอร์ที่เหมาะสมที่สุด
UC-06
จองนัดหมายเวลาเรียน (Appointment Scheduling)
Actor: ผู้เรียน (Student)
Pre-condition: เลือกติวเตอร์ที่ต้องการจากผลการจับคู่
Main Flow: 1. ผู้เรียนเลือกวันนัดหมาย (YYYY-MM-DD) และระบุช่วงเวลาเรียน
2. กรอกหัวข้อหรือเนื้อหาที่ต้องการเน้นเป็นพิเศษ
3. ส่งคำขอนัดหมาย บันทึกลงตาราง Appointment สถานะ 'pending'
4. รายการนัดหมายปรากฏในหน้าต่างตารางนัดหมายของผู้เรียนและติวเตอร์
Post-condition: สร้างนัดหมายใหม่รอการอนุมัติจากติวเตอร์
UC-07
จัดการคำขอนัดหมาย (Manage Appointments)
Actor: ติวเตอร์ (Tutor)
Pre-condition: มีรายการนัดหมายเข้ามาในระบบ
Main Flow: 1. ติวเตอร์ตรวจสอบรายละเอียด วันเวลา และหัวข้อที่นักเรียนขอเรียน
2. กดปุ่ม 'อนุมัติ (Approved)' เพื่อยืนยัน หรือ 'ปฏิเสธ (Declined)'
3. ระบบอัปเดตสถานะในตาราง Appointment และแสดงผลให้ผู้เรียนเห็นทันที
Post-condition: สถานะคำขอนัดหมายเปลี่ยนเป็น Approved หรือ Declined
UC-08
ติดต่อตรงผ่าน LINE Official Account (LINE Direct Link)
Actor: ผู้เรียน, ติวเตอร์
Pre-condition: พบติวเตอร์ที่ต้องการจากผลการค้นหา
Main Flow: 1. ผู้เรียนกดปุ่ม 'ทักทาง LINE OA' จากการ์ดผลลัพธ์ของติวเตอร์
2. ระบบเปิดลิงก์แชท LINE Direct เชื่อมโยงไปยังบัญชีติวเตอร์ทันที
3. ทั้งสองฝ่ายสามารถพูดคุย ส่งเอกสารการสอน หรือยืนยันสถานที่เรียนได้โดยตรง

    DB-->>API: รายการคำขอนัดหมาย

flowchart TD
