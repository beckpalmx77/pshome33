คู่มือการปฏิบัติงานระบบ PSHOME33

ระบบบันทึกรายรับ-รายจ่ายนิติบุคคล และระบบบัญชีแยกประเภททั่วไป (General Ledger)

1. บทนำระบบงาน

ระบบ PSHOME33 เป็นระบบสารสนเทศเพื่อการบริหารจัดการนิติบุคคลหมู่บ้านจัดสรรพฤกษา 33 โดยครอบคลุมตั้งแต่การจัดเก็บค่าส่วนกลาง การลงบันทึกรายจ่ายต่าง ๆ ตลอดจนการประมวลผลข้อมูลเข้าสู่ระบบบัญชีแบบ ระบบบัญชีคู่ (Double-Entry Bookkeeping) เพื่ออำนวยความสะดวกในการจัดทำรายงานทางการเงิน เช่น สมุดรายวันทั่วไป (General Ledger) และรายงานกระแสเงินสด (Cash Flow)

💡 คอนเซปต์หลักของระบบบัญชี PSHOME33:

ทุก ๆ รายการเงินเข้า (Revenue) หรือเงินออก (Expense) ที่ได้รับการอนุมัติยืนยันในฝั่งผู้ดูแลระบบ จะถูกแปลงเป็นรายการบัญชีเดบิต (Dr) และเครดิต (Cr) ลงในสมุดรายวันทั่วไปให้อัตโนมัติ เพื่อป้องกันความผิดพลาดของข้อมูลและการทำงานซ้ำซ้อน

2. การจัดการรายรับ (Income)

รายรับของหมู่บ้านจัดสรรแบ่งออกเป็น 2 ประเภทหลัก คือ รายรับค่าส่วนกลาง และ รายรับอื่น ๆ (รายรับเบ็ดเตล็ด)

2.1 การรับชำระค่าส่วนกลาง (Common Fee Payment)

ดำเนินการผ่านเมนู "จัดการข้อมูลชำระเงินค่าส่วนกลาง" (หน้า manage_common_fee_payment)

1
ตรวจสอบการโอนเงิน/ชำระเงิน

เจ้าหน้าที่นิติบุคคลตรวจสอบหลักฐานการชำระเงิน (สลิปโอนเงิน) ที่ลูกบ้านส่งมาผ่านทาง LINE OA หรือช่องทางติดต่ออื่น ๆ

2
กรอกข้อมูลและยืนยัน

เลือกบ้านเลขที่ที่ต้องการชำระเงิน ระบุยอดเงินชำระ วิธีการชำระเงิน (เงินสด หรือโอนเงิน) วันที่ชำระเงินจริง และช่วงเดือนที่ชำระ (เริ่มต้น - สิ้นสุด)

3
บันทึกบัญชีอัตโนมัติ

เมื่อกดบันทึกและระบบเปลี่ยนสถานะเป็นยืนยัน (payment_status = 'Y') ข้อมูลจะส่งเข้าสมุดรายวันแยกประเภท (GL) ทันทีเป็นรายการ RV (Receive Voucher):
Dr. เงินสด / เงินฝากธนาคาร (1101/1102)
Cr. รายได้ค่าส่วนกลาง (4101)

2.2 การจัดการรายรับอื่นๆ / รายรับเบ็ดเตล็ด (Other Receipts)

ดำเนินการผ่านหน้า "รายรับเบ็ดเตล็ด" (หน้า manage_reciepts)

⚠️ กฎการบันทึกรายรับเบ็ดเตล็ด (เวอร์ชันใหม่):
  • ประเภทรายรับ/รายได้ (Category) จะต้องไม่ถูกปล่อยให้เป็นค่าว่างโดยเด็ดขาด หากกรอกไม่ครบถ้วน ระบบจะมีกล่องแจ้งเตือน Bootbox สีแดงเตือนเจ้าหน้าที่ทันที และจะไม่อนุญาตให้ทำการบันทึกข้อมูล
  • เมื่อบันทึกรายการรายรับเบ็ดเตล็ดและทำการ **อนุมัติ (Approve)** รายการแล้ว ระบบหลังบ้านจะลงบัญชีในสมุดรายวันแยกประเภทให้ทันที โดยเดบิตช่องทางการรับเงิน (เงินสด/เงินฝาก) และเครดิต **รายได้อื่นๆ (4103)**

3. การจัดการใบสำคัญจ่าย (Payment Voucher - PV)

ใบสำคัญจ่าย (PV) ใช้สำหรับบันทึกรายการใช้จ่ายเงินของนิติบุคคลหมู่บ้านจัดสรร เช่น ค่าน้ำ-ไฟส่วนกลาง, ค่าจ้าง รปภ., ค่าจ้างทำความสะอาด หรือซื้ออุปกรณ์เบ็ดเตล็ด ดำเนินการผ่านเมนู "ใบสำคัญจ่าย" (หน้า manage_voucher)

3.1 การสร้างและแก้ไขใบสำคัญจ่าย

  • ช่องข้อมูลที่บังคับกรอก (Required): นอกจาก วันที่เอกสาร และ ชื่อผู้รับเงินแล้ว ปัจจุบันฟิลด์ **"จ่ายเพื่อ" (purpose)** ถือเป็นฟิลด์ที่บังคับกรอก เพื่อให้นักบัญชีและผู้ตรวจสอบบัญชีทราบวัตถุประสงค์ของการจ่ายเงินอย่างชัดเจน
  • การอนุมัติใบสำคัญจ่าย: เมื่อใบสำคัญจ่ายได้รับการอนุมัติ (approve_status = 'Y') ระบบจะลงสมุดรายวันทั่วไป (GL) ด้วยประเภท PV ทันที โดยบันทึกยอดรวม:
    Dr. ค่าใช้จ่ายทั่วไป (5101)
    Cr. เงินสด / เงินฝากธนาคาร (1101/1102)
✨ ฟีเจอร์ใหม่ในตารางแสดงผลใบสำคัญจ่าย:

ในหน้าตารางข้อมูลรวม ได้มีการเพิ่มคอลัมน์ "รายละเอียดค่าใช้จ่าย" (ดึงข้อมูลวัตถุประสงค์มาแสดง) เพื่อช่วยให้เจ้าหน้าที่ค้นหาใบสำคัญจ่ายได้ง่ายขึ้นผ่านแถบค้นหา (Search Box) และยอดจำนวนเงินจ่ายจะแสดงผลเป็นตัวเลขจัดชิดขวา พร้อมจุดทศนิยม 2 ตำแหน่งเสมอตามหลักบัญชีสากล

4. การบันทึกค่าใช้จ่ายย่อย (EXP)

ตาราง ims_expenses เป็นตารางสำหรับจัดเก็บ **"รายละเอียดรายการค่าใช้จ่ายย่อย"** ที่เกิดขึ้นจริงในระบบงาน

4.1 ความเชื่อมโยงระหว่าง ค่าใช้จ่ายย่อย (EXP) กับ ใบสำคัญจ่าย (PV)

เพื่อป้องกันไม่ให้ตัวเลขค่าใช้จ่ายเบิ้ลหรือลงบัญชีซ้ำซ้อน ระบบได้จัดรูปแบบโครงสร้างข้อมูลดังนี้:

ประเภทรายการในตาราง EXP คำอธิบายโครงสร้างข้อมูล การประมวลผลระบบบัญชี (GL)
ผูกกับใบสำคัญจ่าย (PV-%) เป็นรายการย่อยของ PV เช่น ใบสำคัญจ่ายมี 1 ใบ (ยอดรวม 5,000.-) แต่มีค่าใช้จ่ายย่อยแยกเป็น 3 รายการย่อยในตารางนี้ ลงบัญชีจากตัวแม่ (PV) เท่านั้น
ระบบจะลงบัญชีจากยอดรวมของใบสำคัญจ่าย เพื่อป้องกันการลงซ้ำซ้อนสองเท่า
ผูกกับระบบเงินเดือน (PAY%) บันทึกข้อมูลเงินเดือนพนักงาน รปภ. แม่บ้าน และพนักงานสำนักงานนิติบุคคลแต่ละคน เตรียมขยายผล
กำลังจัดเตรียมแนวทางการลงบัญชีแยกแผนกค้างจ่าย
ไม่มีข้อมูลอ้างอิง (doc_ref = '-') เป็นข้อมูลประวัติเก่าในช่วงเริ่มต้นระบบงานช่วงเดือน 06/2025 ไม่นำมาคำนวณซ้ำ
ระบบบันทึกแยกไว้สำหรับรายงานประวัติย้อนหลัง

5. ระบบบัญชีแยกประเภท (General Ledger - GL)

หน้าจอ "สมุดรายวันทั่วไป / บัญชีแยกประเภท" (หน้า manage_gl และ report_gl) ใช้แสดงผลบัญชีคู่ที่ถูกเชื่อมโยงมาจากหน้าจอรายรับและรายจ่าย

5.1 ผังบัญชีเริ่มต้น (Chart of Accounts)

ระบบได้ถูกตั้งค่าผังบัญชีหลักไว้ 5 หมวดหมู่ เพื่อความถูกต้องในการสรุปงบการเงิน:

รหัสบัญชี ชื่อบัญชีแยกประเภท หมวดหมู่หลัก การนำไปใช้งานหลักในระบบ PSHOME33
1101 เงินสด Asset (สินทรัพย์) บันทึกรายรับ/รายจ่ายที่ชำระด้วยเงินสด
1102 เงินฝากธนาคาร Asset (สินทรัพย์) บันทึกรายรับ/รายจ่ายที่ชำระด้วยการโอนผ่านธนาคาร
1103 ลูกหนี้ค่าส่วนกลาง Asset (สินทรัพย์) บันทึกยอดค้างชำระของลูกบ้าน (รอตัดรับชำระ)
4101 รายได้ค่าส่วนกลาง Revenue (รายได้) บันทึกรายรับที่ได้จากการจัดเก็บค่าส่วนกลางรายเดือน
4103 รายได้อื่นๆ Revenue (รายได้) บันทึกรายรับอื่น ๆ เช่น ดอกเบี้ยรับ, ค่าจำหน่ายสติกเกอร์ หรือค่าบริการอื่น
5101 ค่าใช้จ่ายทั่วไป Expense (ค่าใช้จ่าย) บันทึกการใช้จ่ายทั่วไปของนิติบุคคลผ่านใบสำคัญจ่าย

6. ขั้นตอนการปฏิบัติงานประจำวันของเจ้าหน้าที่

เพื่อให้ข้อมูลระบบบัญชีและยอดเงินตรงกันกับบัญชีธนาคารจริง เจ้าหน้าที่นิติบุคคลควรดำเนินงานตามขั้นตอนขั้นตอนดังต่อไปนี้:

1
ลงบันทึกรายรับทันทีเมื่อได้รับเงิน

ไม่ว่าจะรับเงินชำระค่าส่วนกลางหรือค่ารับเงินเบ็ดเตล็ด ให้คีย์ข้อมูลเข้าระบบในวันนั้น ๆ ทันที เลือกวิธีชำระเงินให้ตรงตามหลักฐานจริง (เงินสด หรือ โอนเงิน)

2
สร้างใบสำคัญจ่าย (PV) เมื่อมีการใช้จ่าย

กรอกข้อมูลรายละเอียดของค่าใช้จ่ายในช่อง "จ่ายเพื่อ" และระบุข้อมูลผู้รับเงินให้ละเอียด เมื่อได้รับการอนุมัติจากคณะกรรมการ ให้ตรวจสอบสถานะการลงบัญชีอัตโนมัติ

3
ตรวจสอบรายงานทางการเงินทุกสิ้นวัน

เปิดตรวจสอบหน้า งบกระแสเงินสด (Cash Flow Report) และ สมุดรายวันทั่วไป (GL) เพื่อกระทบยอด (Reconcile) ยอดเงินคงเหลือในระบบกับสมุดบัญชีธนาคารและกล่องเงินสดในสำนักงาน

7. การซิงค์และล้างฐานข้อมูลระบบบัญชี

ในกรณีที่ระบบบัญชีสมุดรายวันทั่วไป (GL) แสดงตัวเลขที่ไม่ตรง หรือมีข้อมูลค้างผ่านรายการจากธุรกรรมรายวัน ระบบจัดเตรียมเครื่องมือในการจัดการบัญชีแยกประเภทดังนี้:

7.1 การประมวลผลผ่านบัญชีแยกประเภทใหม่ทั้งหมด (GL Full Reprocess)

ดำเนินการผ่านหน้าจอ reprocess_all_to_gl.php ซึ่งจัดทำหน้าจอแบบมี Progress Bar และทำงานผ่านระบบ Ajax แบ่งการประมวลผลเป็นชุดๆ เพื่อหลีกเลี่ยงระบบค้างหรือ Timeout:

  • ล้างบัญชีเดิม: ระบบจะทำการเคลียร์ข้อมูลแยกประเภททั่วไป (PV/RV) เก่าทั้งหมดโดยอัตโนมัติ
  • ผ่านรายการใหม่: ดึงธุรกรรมการชำระเงินจริงจาก ims_payment_voucher, ims_house_payment และ ims_reciepts มาทำการประมวลผลบัญชี (เดบิต/เครดิต) ให้ถูกต้องสอดคล้องตรงกัน 100%

7.2 การผ่านรายการค้างโพสต์เข้า GL (GL Sync New Only)

ดำเนินการผ่านหน้าจอ sync_transactions_to_gl.php สำหรับสแกนเฉพาะรายการรับเงินหรือจ่ายเงินที่อนุมัติเข้ามาใหม่แต่ยังไม่ได้ทำการบันทึกลงบัญชีแยกประเภททั่วไป (GL) เพื่ออัปเดตระบบบัญชีให้เป็นปัจจุบันโดยไม่ต้องประมวลผลรายการเก่าซ้ำ

8. API และส่วนติดต่อภายนอก (API & External Integration)

ระบบ PSHOME33 ได้จัดทำช่องทางเชื่อมโยงสำหรับแอปพลิเคชันหรือระบบจัดการภายนอก เพื่อดึงข้อมูลยอดค้างชำระค่าส่วนกลางได้อย่างปลอดภัยและเป็นมาตรฐานสากล:

8.1 API ตรวจสอบยอดค้างชำระค่าส่วนกลาง

เชื่อมต่อผ่านทาง Endpoint api/get_outstanding_fee.php ด้วยพารามิเตอร์แบบ HTTP GET:

  • house_number (จำเป็น): บ้านเลขที่ของลูกบ้านที่ต้องการสืบค้นยอดค้างชำระ เช่น 67/117
  • year (ตัวเลือก): ปี ค.ศ. ที่ต้องการสืบค้นข้อมูลยอดค้าง (หากไม่ระบุจะใช้ปีปัจจุบัน)
  • api_key (จำเป็น): รหัสคีย์ความปลอดภัย PSHOME33_SECURE_API_KEY_2026 หรือระบุผ่าน HTTP Header X-API-KEY เพื่อยืนยันสิทธิ์

คู่มือสำหรับนักพัฒนา: สามารถเข้าไปศึกษารูปแบบตัวอย่างคำขอ, JSON Response ของผลลัพธ์ ตลอดจนทดสอบส่งคำขอผ่านโปรแกรมจำลองหน้าเว็บ (API Sandbox Interface) ได้ที่ไฟล์ api_common_fee.html ในระบบหลัก
