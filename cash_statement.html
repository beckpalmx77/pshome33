รายงานสรุปความเคลื่อนไหวเงินสดย่อย (Petty Cash Statement)

การรับเงินสดย่อย (ims_petty_cash) และจ่ายเงินสดย่อย (ims_expenses) เรียงตามลำดับวันที่และแสดงยอดคงเหลือ

1. แนวคิดและวิธีการประมวลผลข้อมูล (Core Concept & Data Flow)

รายงานชิ้นนี้ทำหน้าที่เสมือน "บัญชีกระแสรายวันเงินสดย่อย" (Bank Statement) ที่จะรวมกิจกรรมการรับเข้าและจ่ายออกให้อยู่ในตารางเดียวกัน โดยใช้เทคนิค SQL UNION ALL และจัดเรียงข้อมูลตามวันที่เพื่อหา "ยอดสะสมคงเหลือ" (Running Balance) ดังนี้:

เงินสดย่อยรับเข้า (Inflow)

ดึงข้อมูลจากตาราง ims_petty_cash โดยมีเงื่อนไขดังนี้:

  • status = 'Y' (ผ่านการอนุมัติ/ยืนยันแล้ว)
  • transaction_type = '+' (รายการรับเงินสดย่อยเข้าคลัง)

เงินสดย่อยจ่ายออก (Outflow)

ดึงข้อมูลจากตาราง ims_expenses โดยมีเงื่อนไขดังนี้:

  • approve_status = 'Y' (รายการค่าใช้จ่ายที่อนุมัติแล้ว)
  • petty_cash_status = 'Y' (ระบุเป็นเงินสดย่อย)

สูตรการคำนวณยอดคงเหลือสะสม (Running Balance Calculation)
ยอดคงเหลือรอบปัจจุบัน = ยอดคงเหลือยกมา + ยอดรับเข้า (Inflow) - ยอดจ่ายออก (Outflow)
2. การออกแบบชุดคำสั่ง SQL (SQL Query Design)

เนื่องจากฟิลด์วันที่ในตาราง ims_expenses เป็น varchar(10) (เก็บเป็น string เช่น 'dd-mm-yyyy' หรือ 'yyyy-mm-dd') ในขณะที่ ims_petty_cash เก็บเป็น date จึงจำเป็นต้องใช้ฟังก์ชัน CASE และ STR_TO_DATE เพื่อแปลงประเภทข้อมูลให้อยู่ในรูปของ Date ที่ถูกต้องสำหรับการเรียงลำดับ (ORDER BY) ดังนี้:

SELECT 
    'receipt' AS source_type,
    id AS source_id,
    doc_date AS txn_date,
    doc_no AS doc_id,
    description AS description,
    received_from AS contact_person,
    amount AS inflow,
    0.00 AS outflow
FROM ims_petty_cash
WHERE status = 'Y' AND transaction_type = '+'
  AND doc_date BETWEEN STR_TO_DATE(:start_date, '%d-%m-%Y') AND STR_TO_DATE(:end_date, '%d-%m-%Y')

UNION ALL

SELECT 
    'expense' AS source_type,
    id AS source_id,
    CASE 
        WHEN expense_date REGEXP '^[0-9]{4}-[0-9]{2}-[0-9]{2}$' THEN STR_TO_DATE(expense_date, '%Y-%m-%d')
        WHEN expense_date REGEXP '^[0-9]{2}-[0-9]{2}-[0-9]{4}$' THEN STR_TO_DATE(expense_date, '%d-%m-%Y')
        ELSE NULL 
    END AS txn_date,
    doc_id AS doc_id,
    description AS description,
    receipt_name AS contact_person,
    0.00 AS inflow,
    amount AS outflow
FROM ims_expenses
WHERE petty_cash_status = 'Y' AND approve_status = 'Y'
  AND (CASE 
        WHEN expense_date REGEXP '^[0-9]{4}-[0-9]{2}-[0-9]{2}$' THEN STR_TO_DATE(expense_date, '%Y-%m-%d')
        WHEN expense_date REGEXP '^[0-9]{2}-[0-9]{2}-[0-9]{4}$' THEN STR_TO_DATE(expense_date, '%d-%m-%Y')
        ELSE NULL 
  END BETWEEN STR_TO_DATE(:start_date, '%d-%m-%Y') AND STR_TO_DATE(:end_date, '%d-%m-%Y'))

ORDER BY txn_date ASC, doc_id ASC;
ข้อควรพิจารณาเรื่อง "ยอดยกมา" (Opening Balance)

หากมีการกรองข้อมูลตามช่วงวันที่ (เช่น 01-06-2026 ถึง 30-06-2026) เพื่อให้ยอดคงเหลือ (Running Balance) ถูกต้องในระบบ จำเป็นต้องคำนวณ ยอดยกมาก่อนวันที่เริ่มต้น (Opening Balance) โดยดึงผลรวมของ Inflow ลบ Outflow ก่อนหน้า :start_date มาตั้งเป็นแถวแรกของตารางก่อน

4. ขั้นตอนและแผนการพัฒนาพัฒนาจริง (Implementation Plan Steps)
1
สร้างหน้าจอหลักสำหรับการกรองเงื่อนไขวันที่ (petty_cash_statement_report.php)

สร้าง UI คล้ายกับรายงานค่าใช้จ่าย มีกล่องปฏิทินเลือกวันที่เริ่มต้นและวันที่สิ้นสุด พร้อมปุ่มเรียกดูข้อมูล (Show Data), ปุ่มออกรายงาน PDF และปุ่มออก Excel

2
พัฒนาระบบคำนวณและดึงข้อมูลด้วย PHP/PDO (model/manage_petty_cash_statement.php)

สร้างฟังก์ชันส่ง Parameter วันที่และประมวลผลคำสั่ง UNION SQL เพื่อดึงรายการทั้งหมด และวนซ้ำ (Loop) ในการคำนวณยอดเงินสะสมคงเหลือ (Running Balance) รวมถึงการคำนวณยอดยกมาก่อนวันเริ่มต้น

3
สร้างหน้าจอแสดงผลข้อมูลบนหน้าเว็บบราวเซอร์ (HTML / Datatable)

ใช้ Bootstrap Table และ DataTables JS เพื่อให้สามารถค้นหารายการ, จัดลำดับ, และจัดกลุ่มข้อมูลได้อย่างสะดวกรวดเร็วบนบราวเซอร์ก่อนกดพิมพ์

4
สร้างระบบพิมพ์รายงานเป็นไฟล์ PDF ด้วย TCPDF (export_process/petty_cash_statement_pdf.php)

จัดตารางรายงานสรุปความเคลื่อนไหวทางบัญชีในรูปแบบกระดาษแนวนอน (Landscape) เพื่อการนำเสนอผู้บริหารหรือแนบใบสำคัญบัญชี

5
ลงทะเบียนเมนูในระบบ (menu_sub)

เพิ่มรายการเมนูย่อยภายใต้เมนูรายงานการเงิน (Financial Report) เพื่อให้ผู้ใช้สามารถคลิกใช้งานหน้าจอได้อย่างสะดวก
